# 天猫同行比价监控系统设计说明

日期：2026-08-13  
第一期店铺：星空乐器专营店  
第一期平台：天猫  
提醒渠道：企业微信运营群

## 2026-08-19 数据来源决策

- ERP、商品资料、匹配、比价、预警、后台和企业微信通知全部由公司自建。
- 天猫公开商品数据由合规的外部数据 API 提供，外部服务只负责返回原始商品与价格数据，不承载公司的比价规则和运营数据。
- 数据接入使用可替换的 `CommerceProvider` 契约，后续更换供应商时不修改匹配、价格和预警模块。
- 第一期不使用淘宝客 API，也不自建需要淘宝账号登录的网页采集程序。
- 正式接入前必须验证供应商的数据来源说明、关键词搜索覆盖范围、SKU 价格准确率、更新频率、限额和故障响应机制。

## 1. 项目目标

建立一套只负责监控和提醒、不自动改价的天猫比价系统。运营录入需要监控的标准型号后，系统自动搜索整个天猫，将同行商品分为裸机和套装两个价格池，并与星空乐器专营店的对应商品比较。

只要可比同行的实际到手价低于我方对应价格，无论差价大小，系统都产生预警并发送到统一的企业微信运营群。最终价格是否调整，由运营人工决定。

## 2. 第一期范围

### 包含

- 运营通过 Excel 批量导入重点型号。
- 后台支持单独新增、修改、停用监控型号。
- 通过外部数据 API，根据品牌、标准型号、别名、包含词和排除词搜索天猫公开商品。
- 识别星空乐器专营店商品和同行商品。
- 裸机与套装分开归类、分开比价。
- 采集页面标价、活动价、公开优惠券后价、SKU 规格、店铺、链接、赠品描述、库存状态和采集时间。
- 保存价格快照和页面截图，方便运营复核。
- 低价异常通过企业微信群机器人提醒。
- 后台记录运营处理状态和处理意见。

### 不包含

- 不自动修改天猫价格。
- 不在第一期覆盖京东、拼多多、抖音等平台。
- 不在第一期自动导入星空乐器专营店全部商品。
- 不把不同配置套装的折算价直接作为自动降价依据。
- 不采集必须由特定个人账号、会员等级或私聊客服才能获得的非公开价格作为确定价格；此类信息只标记为待人工核对。

## 3. 业务规则

### 3.1 可比商品定义

裸机可比必须同时满足：

- 品牌一致。
- 标准型号一致。
- 版本、代际、颜色或核心规格一致；若颜色不影响公司定价，可由运营配置为可互比。
- 同为国行新品，不能混入二手、租赁、维修、定金、补差价、空盒、配件等链接。
- 同为单机，不含会显著改变价格的主配件。

套装可比优先级：

1. 主产品和主要配件品牌型号、数量完全相同：可直接比较套装到手价。
2. 主产品相同，但配件不同：进入“不同配置套装”列表，显示套装总价与折算参考价，标记为人工核对。
3. 无法识别主产品或主要配件：进入待人工分类，不触发确定性低价预警。

### 3.2 价格定义

- 页面价：商品页展示的当前价格。
- 公开优惠：所有用户可见、无需私聊客服的店铺券、平台券、满减等。
- 实际到手价：页面价减去当前可确定的公开优惠，加上必须支付的费用。
- 裸机比较价：裸机 SKU 的实际到手价。
- 同配置套装比较价：完整套装的实际到手价。
- 套装折算参考价：套装实际到手价减去配件标准价值，仅供运营判断，不作为第一期确定性降价依据。

如果价格是区间价，必须进入具体 SKU 后采集对应规格价格，不能用搜索列表中的最低引流价直接比较。

### 3.3 预警规则

- 当 `同行可比价 < 我方可比价` 时立即产生预警，不设最低金额或比例门槛。
- 价格相同或同行更高时不提醒。
- 同一同行商品、同一 SKU、同一价格只提醒一次。
- 同行价格再次下降时重新提醒。
- 已处理后若价格重新低于我方，也重新建立事件。
- 不同配置套装价格更低时发送“人工核对”提醒，不直接判断我方应降价。
- 数据提供商限流、字段缺失、契约变化或服务异常时发送系统异常提醒，不能把缺失价格当作低价。

## 4. 检查时间

时区统一使用 Asia/Shanghai。

运营时段每小时检查一次，共 10 次：

`09:30、10:30、11:30、12:30、13:30、14:30、15:30、16:30、17:30、18:30`

夜间补查 2 次：

`22:30、03:30`

每天合计 12 次。夜间发现的异常立即发企业微信群，并保留在次日运营待办中。

## 5. Excel 导入模板

模板文件包含 4 张工作表。

### 5.1 监控型号

| 字段 | 必填 | 示例 | 规则 |
|---|---|---|---|
| 监控编号 | 是 | MON-0001 | 唯一编号，不重复 |
| 是否启用 | 是 | 是 | 仅允许“是/否” |
| 品牌 | 是 | RME | 使用统一品牌名称 |
| 标准型号 | 是 | Babyface Pro FS | 不写营销词 |
| 类目 | 是 | 声卡 | 声卡、麦克风、监听音箱等 |
| 搜索关键词 | 是 | RME Babyface Pro FS | 用于天猫搜索 |
| 型号版本 | 否 | FS新版 | 区分旧款、新款、颜色或接口版本 |
| 必须包含词 | 否 | Babyface;FS | 多个词用英文分号分隔 |
| 排除词 | 否 | 二手;租赁;定金;维修 | 多个词用英文分号分隔 |
| 我方商品链接 | 是 | https://example.com/demo/1 | 星空乐器专营店商品链接 |
| 我方SKU规格 | 是 | Babyface Pro FS单机 | 必须能定位具体 SKU |
| 比价类型 | 是 | 裸机 | 仅允许“裸机/套装” |
| 套装编号 | 条件必填 | PKG-RME-001 | 裸机留空，套装必填 |
| 颜色是否可互比 | 是 | 否 | 仅允许“是/否” |
| 负责人 | 是 | 运营A | 企业微信提醒中显示 |
| 备注 | 否 | 国行新版 | 补充口径 |

同一标准型号有一个裸机和两个套装时，应填写三行，并分别指定比价类型及套装编号。

### 5.2 套装明细

| 字段 | 必填 | 示例 | 规则 |
|---|---|---|---|
| 套装编号 | 是 | PKG-RME-001 | 必须与监控型号一致 |
| 主产品品牌 | 是 | RME | 统一名称 |
| 主产品型号 | 是 | Babyface Pro FS | 标准型号 |
| 配件类型 | 是 | 麦克风 | 麦克风、音箱、线材、支架、服务等 |
| 配件品牌 | 否 | 森海塞尔 | 无品牌赠品可留空 |
| 配件型号或名称 | 是 | MK4 | 每个配件单独一行 |
| 数量 | 是 | 1 | 正整数 |
| 单件标准价值 | 是 | 1800 | 用于套装折算，人民币元 |
| 是否核心配件 | 是 | 是 | 核心配件不同则不能视为同配置 |
| 备注 | 否 | 国行标配 | 补充说明 |

### 5.3 型号别名

| 字段 | 必填 | 示例 | 规则 |
|---|---|---|---|
| 品牌 | 是 | RME | 统一名称 |
| 标准型号 | 是 | Babyface Pro FS | 必须存在于监控型号表 |
| 常见写法 | 是 | 娃娃脸FS | 每个别名单独一行 |
| 匹配类型 | 是 | 有效别名 | 有效别名、排除别名 |
| 备注 | 否 | 国内常用简称 | 补充说明 |

### 5.4 填写说明

说明字段定义、填写示例、裸机和套装拆分规则、常见错误及导入步骤。企业微信群机器人 Webhook 不写入模板，由系统管理员在后台单独配置。

## 6. 系统页面

第一期后台包含以下页面：

1. 监控总览：今日扫描次数、监控型号数、低价事件数、待处理数、采集异常数。
2. 型号管理：导入 Excel、新增型号、编辑规则、启停监控。
3. 裸机比价：我方价格与所有可比同行价格排行。
4. 套装比价：同配置套装和不同配置套装分栏展示。
5. 待人工分类：无法确定裸机、套装、版本或规格的搜索结果。
6. 预警中心：待处理、已改价、不跟价、误报、继续观察。
7. 历史价格：查看我方和同行的价格变化、截图和采集时间。
8. 系统设置：企业微信机器人、检查计划、店铺名称和基础词库。

## 7. 企业微信提醒

企业微信群机器人消息至少包含：

- 预警等级：确定低价或人工核对。
- 品牌、标准型号、裸机或套装。
- 我方店铺、我方 SKU、我方实际到手价。
- 同行店铺、同行 SKU、同行实际到手价。
- 差额和差额比例。
- 优惠、赠品和调试服务摘要。
- 同行商品链接。
- 价格截图或后台详情链接。
- 首次发现时间、最近发现时间和负责人。

企业微信群用于通知，运营处理状态在系统后台操作，避免仅靠群聊回复造成状态丢失。

## 8. 数据处理流程

1. 运营导入监控型号和规则。
2. 调度器在设定时间触发采集任务。
3. 系统通过同一数据提供商或后续接入的商家接口读取我方具体 SKU 价格。
4. 系统通过 `CommerceProvider` 根据关键词搜索天猫公开商品并获取候选商品详情。
5. 数据适配器将供应商结果统一为品牌、型号、版本、SKU、价格、优惠、赠品、库存和采集时间。
6. 规则引擎过滤无效链接并进行裸机、套装分类。
7. 匹配引擎判断是否可比，并给出匹配依据和置信度。
8. 价格引擎计算实际到手价和套装折算参考价。
9. 预警引擎判断同行是否低于我方，并执行去重。
10. 保存价格历史、截图和采集日志。
11. 将新异常推送到企业微信运营群。
12. 运营在后台标记处理结果。

## 9. 运营处理状态

- 待处理：新发现，尚未判断。
- 已改价：运营已调整我方价格。
- 不跟价：确认同行低价但决定不调整，必须填写原因。
- 误报：型号、版本、配置或价格识别错误，必须选择误报原因。
- 继续观察：暂不处理，保留在待办列表。

常用“不跟价”原因包括：非授权店、非国行、赠品不同、服务不同、库存异常、活动临时价、低于利润底线和品牌控价限制。

## 10. 数据与安全要求

- 企业微信 Webhook、登录凭据和平台会话必须加密保存，不写入 Excel 和日志明文。
- 外部数据 API 密钥必须加密保存，不写入 Excel、页面响应或明文日志。
- 系统区分管理员和运营账号；只有管理员可修改调度、店铺和通知配置。
- 所有监控规则、价格事件和处理状态保留操作记录。
- 外部数据提供商必须提供数据来源与合规使用说明；未经确认的数据源不得接入生产环境。
- 供应商字段缺失、结构变化、限流或服务异常时停止对应任务并报警，禁止用错误字段继续比较。

## 11. 验收标准

- Excel 模板可以导入，并能明确指出错误行和错误字段。
- 试点型号能够搜索到天猫候选商品并保留原始链接。
- 外部数据提供商可以通过契约测试，且更换测试适配器时不影响匹配、价格和预警模块。
- 裸机和套装不会混在同一价格排行中。
- 搜索列表区间最低价不会被误当成目标 SKU 价格。
- 可比同行价格只要低于我方价格，即产生一次预警。
- 同价格重复扫描不重复通知；再次降价会重新通知。
- 每天按 12 个设定时间执行，并显示每次任务成功或失败。
- 企业微信群能收到完整预警信息。
- 运营能够将事件标记为已改价、不跟价、误报或继续观察。
- 每条预警可以回查采集时间、商品链接、价格依据和截图。

## 12. 上线顺序

1. 生成 Excel 模板并录入 20 至 50 个重点型号。
2. 用 Babyface Pro FS、Zen Quadro、森海塞尔 MK4、纽曼 105、Kali LP-UNF 等型号验证匹配规则。
3. 先人工运行采集，修正别名、排除词和套装分类。
4. 接入每天 12 次自动调度。
5. 接入企业微信群机器人。
6. 试运行一周，统计误报率、漏报率和采集成功率。
7. 稳定后扩大到星空乐器专营店更多型号。

## 13. 当前假设

- 夜间两次检查采用 22:30 和 03:30。
- 第一批型号由运营通过 Excel 录入，不自动抓取全店商品。
- 第一批监控 20 至 50 个重点型号。
- 正式数据供应商尚未锁定；开发阶段使用脱敏固定样例和手工导入适配器，生产上线前再接入通过验证的供应商 API。
- 只有明确可比的裸机或同配置套装才触发确定低价；不同配置套装只触发人工核对。
- 企业微信统一发送到一个运营群，具体机器人 Webhook 在开发部署时由管理员提供。
