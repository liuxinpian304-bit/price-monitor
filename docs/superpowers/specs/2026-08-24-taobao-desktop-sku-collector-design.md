# 淘宝桌面版全 SKU 比价采集设计

日期：2026-08-24
状态：已确认，待实施
第一期平台：淘宝、天猫
我方店铺：星空乐器专营店
提醒渠道：企业微信运营群

## 1. 文档关系与决策变更

本设计扩展《天猫同行比价监控系统设计说明》，并替换其中 2026-08-19 的数据来源决策：第一期不再依赖淘宝客 API 或付费商品数据 API，而是使用用户已经安装并登录的淘宝桌面版作为公开商品信息来源。

原设计中的型号管理、裸机与套装分池、人工改价、低价告警、历史记录和运营处理流程继续有效。`CommerceProvider` 保持可替换，桌面采集器作为新的数据提供实现，未来仍可接入合规 API。

## 2. 目标

建立一个本地桌面采集器。对每个启用的监控型号，它在淘宝桌面版中搜索全淘宝结果，检查前 50 个搜索位置，打开其中每一个商品并遍历全部有效 SKU，然后将标准化结果交给现有比价系统。

系统以星空乐器专营店的同配置 SKU 为基准。同行同配置 SKU 的预计单件到手价只要低于我方，无论差价是否超过 1 元，都生成提醒。系统只监控、记录和通知，不自动修改店铺价格。

## 3. 范围

### 3.1 包含

- 淘宝桌面版登录状态下的型号搜索。
- 每个型号前 50 个搜索位置的读取、排名记录和商品去重。
- 每个商品全部可选且有效的 SKU 组合遍历。
- 搜索列表、商品详情、SKU、店铺、活动和价格证据保存。
- 店铺优惠后价与可确定公开优惠的融合计算。
- 我方与同行使用同一价格计算口径。
- 品牌、型号、版本、裸机、套装和主要配件匹配。
- Mac 辅助功能驱动和 Windows UI Automation 驱动。
- 每个型号一条逻辑告警，以及可查看、可导出的完整 SKU 运行报告。
- 每天 12 个既定检查时间的任务调度。

### 3.2 不包含

- 自动修改淘宝或天猫商品价格。
- 绕过验证码、登录验证、访问限制或平台风控。
- 读取或导出淘宝桌面版 Cookie、令牌及其他登录凭据。
- 使用会员等级、个人红包、88VIP、私聊客服或不向所有消费者公开的价格触发确定性低价告警。
- 将不同配置套装直接当作同款自动比较。
- 第一阶段覆盖京东、拼多多、抖音等其他平台。

## 4. 核心架构

系统由四部分组成：

1. 管理后台：维护监控型号、我方商品链接、SKU 规则、检查计划和企业微信配置，展示运行进度与结果。
2. API 与任务队列：创建采集任务、分配给在线采集器、保存进度、执行匹配和价格计算、产生告警。
3. 本地桌面采集器：控制淘宝桌面版，完成搜索、详情页访问、SKU 遍历和证据采集。
4. 平台驱动：Mac 通过系统辅助功能访问界面；Windows 通过 UI Automation 访问界面。平台差异只存在于驱动层。

桌面采集器使用共享的工作流、数据契约、重试规则和任务状态。平台驱动必须实现以下能力：

- 发现淘宝桌面版是否运行、是否登录和是否可交互。
- 聚焦搜索框并提交关键词。
- 滚动结果列表并读取前 50 个搜索位置。
- 打开指定搜索结果并获得稳定的商品标识或完整链接。
- 读取店铺、标题、活动、价格、库存和 SKU 维度。
- 选择一个有效 SKU 组合并等待页面价格稳定。
- 返回上一页并继续下一个结果。
- 检测验证码、登录失效、页面空白和结构变化。

三台电脑上的采集器连接同一个已配置、已配对的中央 API，并只接受该 API 分配的任务。开发阶段允许 API 与采集器运行在同一台电脑；正式分片时，其他电脑通过公司受控网络连接中央 API。采集器不保存企业微信 Webhook，也不直接做价格判断；匹配、计算、去重和通知仍由服务端模块负责。

## 5. 任务与运行状态

每个“监控型号 + 检查时间”形成一个逻辑任务。任务状态如下：

- `QUEUED`：等待空闲采集器。
- `SEARCHING`：正在搜索并建立前 50 个位置清单。
- `SCANNING_ITEMS`：正在逐个访问商品。
- `SCANNING_SKUS`：正在遍历当前商品的有效 SKU。
- `PAUSED_LOGIN`：登录失效，等待人工重新登录。
- `PAUSED_CHALLENGE`：出现验证码或平台验证，等待人工处理。
- `PARTIAL_FAILED`：部分商品或 SKU 无法读取，其他结果已经保存。
- `SUCCEEDED`：前 50 个搜索位置全部处理或有明确排除原因。
- `FAILED`：搜索本身失败，无法形成可用报告。

系统在每个 SKU 完成后保存检查点。程序关闭或短暂异常后可以从下一个未完成 SKU 恢复，不重复保存证据或发送相同告警。

同一台电脑一次只执行一个淘宝桌面任务。同一型号已有未结束任务时，新的定时触发不会并发执行；系统合并重复排队任务并记录未按时完成的检查时间。

## 6. 搜索前 50 的定义

- “前 50”指当前关键词搜索结果中，按页面展示顺序出现的前 50 个商品位置。
- 普通结果和明确标记的广告结果都纳入位置计数，并记录是否为推广位。
- 同一商品在多个位置重复出现时保留所有排名证据，但详情页只采集一次。
- 采集器必须处理滚动加载，直到得到 50 个位置或页面明确没有更多结果。
- 少于 50 个结果时保存实际数量，不以空白数据补足。
- 无法获得稳定商品标识或完整链接时，该位置标记为 `MISSING_ITEM_ID`，不能静默视为已完成。

每个搜索位置至少保存：搜索词、排名、标题、店铺、列表价格区间、推广标记、商品标识、完整链接和读取时间。

## 7. 全部 SKU 的定义与遍历

“全部 SKU”指商品详情页中当前可选择的所有有效 SKU 组合，不只是搜索列表最低价或默认选中的规格。

采集器先读取 SKU 维度和选项，再遍历所有可用组合：

1. 选择当前组合中的全部维度。
2. 确认选中状态与目标组合一致。
3. 等待 SKU 标识、价格和活动区域停止变化。
4. 读取库存、原价、活动价、优惠和页面说明。
5. 保存该组合证据后继续下一组合。

被页面禁用的无效组合不点击，但保存选项和禁用原因。商品的有效组合过多、页面只加载部分选项或组合关系无法确定时，不截断后假装完整；任务标记为 `SKU_ENUMERATION_INCOMPLETE` 并进入人工复核。

同一商品的不同 SKU 即使价格相同，也分别保留记录。SKU 记录至少包含：商品标识、SKU 标识、完整规格文本、结构化属性、库存状态、价格字段、活动字段、证据和采集时间。

## 8. 价格计算口径

我方和同行完全使用相同口径。每个 SKU 保存以下价格：

- 原价：详情页明确展示的优惠前价格。
- 活动价：当前 SKU 页面显示的店铺优惠后价或活动售价。
- 可确定公开优惠：当前消费者可见，且购买当前 SKU 单件时满足条件的优惠券、直减和满减。
- 必付费用：页面明确要求购买该 SKU 必须支付的费用。
- 预计单件到手价：`活动价 - 可叠加公开优惠 + 必付费用`。

只有页面明确说明可以叠加的优惠才同时计算。单件金额未达到门槛的满减、必须购买多件或跨商品凑单的活动不直接扣减。优惠门槛、适用 SKU、叠加关系或金额无法确认时，保存活动原文并将价格置信度设为 `MANUAL_REVIEW`。

会员专享、个人红包、88VIP、私聊客服价和因账号差异产生的优惠不进入确定性比较。赠品和远程调试服务单独记录，不擅自折算为现金优惠。

价格置信度分为：

- `CONFIRMED`：活动价和全部使用的优惠均可由当前 SKU 页面确定。
- `ESTIMATED`：页面给出到手价，但部分计算明细不完整，仅供运营参考。
- `MANUAL_REVIEW`：无法确认 SKU 对应价格、优惠门槛或叠加关系。

只有 `CONFIRMED` 的同配置价格触发确定性低价告警。`ESTIMATED` 和 `MANUAL_REVIEW` 只进入人工复核。

## 9. 我方价格基准

每条监控规则必须配置我方商品链接和目标 SKU 规则。搜索结果中识别到店铺名精确等于“星空乐器专营店”时，也记录其搜索排名，但我方基准优先从已配置的商品链接读取，避免我方商品未进入搜索前 50 时失去比较基准。

我方商品同样遍历全部有效 SKU，并按品牌、标准型号、版本、裸机或套装配置匹配监控规则。无法定位我方目标 SKU、我方商品下架或我方价格置信度不足时，本次任务不得产生低价结论，而是发送“我方基准缺失”系统提醒。

## 10. 商品与 SKU 匹配

匹配同时使用商品标题、所选 SKU 文本、店铺、结构化属性和运营词库。结果分为：

- `EXACT`：品牌、型号、版本和配置均符合，可自动比较。
- `REVIEW`：主型号可能一致，但版本、配件、成色、区域或配置存在不确定性。
- `EXCLUDED`：二手、租赁、定金、维修、样机、空盒、单独配件、其他型号或明确不同配置。

裸机只与同版本裸机比较。套装只有在主产品、主要配件型号和数量一致时才是 `EXACT`；配件不同的套装进入 `REVIEW`。例如目标为 7506 时，M1、MV1、展示样机、单独转换线以及只含配件的 SKU 均不能作为 7506 裸机低价。

自动告警条件为：

`同行匹配结果 = EXACT`，且双方价格置信度均为 `CONFIRMED`，且 `同行预计单件到手价 < 我方预计单件到手价`。

差价为 0.01 元也提醒，不设置金额或比例门槛。

## 11. 结果报告与企业微信

每次运行生成完整报告，包含前 50 个搜索位置、全部已读取 SKU、排除原因、人工复核项、读取失败项、我方基准和低价结果。后台支持按型号、店铺、商品、SKU、匹配状态和价格状态筛选，并支持导出。

企业微信按型号生成一条逻辑汇总提醒，只在发现新低价或已有价格进一步下降时发送。消息至少包含：

- 型号、裸机或套装、检查时间和扫描完成度。
- 我方 SKU、活动价、公开优惠和预计到手价。
- 每个低价同行的店铺、搜索排名、商品标题、SKU、活动价、公开优惠、预计到手价、差额和链接。
- 价格置信度、匹配依据、异常数量和完整报告入口。

如果低价 SKU 数量超过企业微信单条消息限制，群内仍只发送一条摘要和完整报告入口，不连续刷屏。全部 SKU 明细保存在系统报告中。

告警以“监控规则 + 同行商品 + 同行 SKU + 我方 SKU + 同行到手价”为去重键。同一价格重复扫描不重复发送；同行价格进一步下降、我方价格变化后重新形成低价，或已恢复后再次低于我方时重新提醒。

## 12. 检查时间与容量管理

时区使用 `Asia/Shanghai`。保持现有 12 个检查时间：

`03:30、09:30、10:30、11:30、12:30、13:30、14:30、15:30、16:30、17:30、18:30、22:30`

“前 50 个商品 × 全部 SKU”属于高交互量任务。系统不能在没有实测数据时承诺所有型号都能在一小时内完成。第一阶段必须记录每个型号的搜索耗时、商品平均耗时、SKU 数量、完成率和每小时吞吐量，再决定单台电脑可承载的型号数。

容量不足时采用以下顺序处理：

1. 不减少单个任务的前 50 覆盖和全 SKU 要求。
2. 使用两台 Mac 和一台 Windows 分片执行不同型号。
3. 合并同一型号尚未开始的重复时间任务，避免队列无限累积。
4. 在后台明确显示未按计划完成的型号，不把跳过记录为成功。

第一期先运行单个型号“索尼 7506”，测得稳定吞吐量后再逐步增加型号。Windows 分片只有在真实 Windows 电脑通过验收后才投入正式任务。

## 13. 桌面运行条件

- 淘宝桌面版必须已安装并保持登录。
- 电脑屏幕必须保持解锁，淘宝桌面版能够获得前台交互。
- Mac 需要为采集器授予辅助功能权限；Windows 需要允许 UI Automation 控制淘宝桌面版。
- 采集期间用户尽量不操作该电脑的鼠标和键盘，避免选择状态被改变。
- 同一淘宝账号是否允许多台电脑同时登录，以平台实际规则为准；系统不尝试绕过登录限制。

采集器启动时执行环境诊断。应用未安装、版本未知、权限缺失、未登录或界面结构不兼容时，任务不开始，并给出可执行的修复提示。

## 14. 错误处理与恢复

- 普通页面超时：当前步骤最多重试 2 次，仍失败则记录证据并继续下一商品。
- 商品下架或无库存：保存状态，不当作低价。
- 登录失效：进入 `PAUSED_LOGIN`，通知运营重新登录。
- 验证码或平台验证：进入 `PAUSED_CHALLENGE`，不自动处理。
- 页面结构变化：进入 `PARTIAL_FAILED` 或 `FAILED`，保存辅助功能快照和截图，通知维护人员更新驱动。
- SKU 选中状态与目标不一致：不保存价格结论，标记 `SKU_SELECTION_MISMATCH`。
- 价格在等待期内持续变化：标记 `PRICE_UNSTABLE`，进入人工复核。
- 企业微信发送失败：先保存告警，再按既定退避策略重试，不能因通知失败丢失事件。

任何部分失败都必须显示“已检查商品数、已检查 SKU 数、失败数和未完成数”。不能将部分成功显示为完整成功。

## 15. 数据与安全

- 企业微信 Webhook 继续由服务端加密保存，不进入采集器、Excel、Git 或日志。
- 采集器不获取淘宝密码、Cookie、会话令牌或 AppSecret。
- API 为每台采集器签发独立配对令牌，令牌不得输出到日志；停用某台电脑时可以单独撤销。
- 非本机连接必须使用公司受控网络和加密传输，中央 API 不直接暴露到公网。
- 商品截图和界面快照可能包含账号信息，默认只在本地受控目录保存，并支持配置保留期限。
- 日志对店铺账号、配对令牌、Webhook 和本机路径进行脱敏。
- 公开 GitHub 仓库只保留模拟数据和脱敏截图，不提交真实账号、商品证据和价格历史。
- 上线前由公司确认桌面自动化使用方式符合平台规则和公司的账号管理要求。

## 16. 跨平台边界

业务工作流和数据契约必须通过跨平台测试。Mac 与 Windows 只分别实现 `DesktopDriver`，不得复制匹配、价格或告警逻辑。

由于当前开发环境只能直接验证 Mac 淘宝桌面版，Windows 驱动需要在用户的 Windows 电脑上完成辅助功能树诊断、真实页面试跑和安装包验收。在真实 Windows 试跑通过前，项目可以标记“Windows 驱动已开发”，但不能标记“Windows 生产可用”。

淘宝桌面版升级后，驱动通过应用版本和界面能力探测决定是否继续。未知版本默认停止自动任务，完成兼容性验证后再放行。

## 17. 测试与验收

### 17.1 契约与规则测试

- 相同原始页面数据在 Mac 和 Windows 驱动后生成相同标准化结果。
- 活动价、单件可用券、满减门槛、不可叠加优惠和必付费用计算正确。
- 裸机、同配置套装、不同配置套装、样机、配件和其他型号正确分类。
- 低 0.01 元会提醒，相同或更高不提醒。
- 同价重复扫描不重复提醒，进一步降价会再次提醒。

### 17.2 Mac 实机验收

- 使用“索尼 7506”完成一次前 50 个搜索位置采集。
- 每个可访问商品的全部有效 SKU 都有记录或明确失败原因。
- 切换 SKU 后读取的是对应 SKU 价格，不使用默认最低价替代。
- 星空乐器专营店的目标 SKU 能作为我方基准。
- 低价结果能够生成完整报告并发送企业微信摘要。
- 登录失效、验证码和页面结构异常会暂停，不继续产生错误价格。

### 17.3 Windows 实机验收

- 在 Windows 淘宝桌面版完成与 Mac 相同的“索尼 7506”验收用例。
- 结果字段、匹配结论和价格计算与 Mac 契约一致。
- 安装、权限配置、启动、暂停和恢复步骤有独立操作文档。

## 18. 分阶段交付

1. 建立桌面采集数据契约、任务状态和固定页面测试样例。
2. 完成 Mac 驱动最小验证：搜索、前 50、打开详情和切换 SKU。
3. 接入我方基准、匹配、活动价计算、完整报告和告警去重。
4. 接入企业微信汇总提醒和每天 12 次任务调度。
5. 在 Mac 上以“索尼 7506”连续试运行，统计完整率、误报率和耗时。
6. 完成 Windows 驱动、诊断工具和安装说明。
7. 在真实 Windows 电脑验收后，把三台电脑加入分片调度。
