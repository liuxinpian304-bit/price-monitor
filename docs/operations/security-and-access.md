# 权限与秘密配置说明

## 1. 角色边界

| 能力 | OPERATOR 运营 | ADMIN 管理员 |
| --- | --- | --- |
| 查看总览、比价、预警和历史 | 可以 | 可以 |
| 处理预警、填写原因和备注 | 可以 | 可以 |
| 修改型号、启停和导入 Excel | 不可以 | 可以 |
| 修改检查计划和数据源 | 不可以 | 可以 |
| 更新企业微信 Webhook 和数据 API 密钥 | 不可以 | 可以 |
| 查看密钥明文 | 不可以 | 不可以 |

所有修改操作应记录真实人员标识、操作时间、对象和 before/after 审计信息。

## 2. 身份认证边界

API 默认只监听 `127.0.0.1`，不能直接暴露到公网。生产环境必须通过公司统一身份认证或可信反向代理访问。代理应删除客户端原始的 `x-role`、`x-actor-id` 等头，再根据已认证身份写入可信角色和人员标识。

本地开发页面使用简化身份头便于联调，不等同于生产认证。未接入统一身份认证前，不允许把管理后台部署到可被外部网络直接访问的位置。

## 3. 密钥保存

企业微信 Webhook 和外部数据 API 密钥使用 AES-256-GCM 加密后存入数据库。页面和公共 API 只返回“已配置/未配置”，不回显密钥。`SETTINGS_MASTER_KEY` 只存在于进程环境或服务器秘密管理系统。

禁止把以下内容放入 Git、Excel、截图、工单正文或普通聊天：

- `SETTINGS_MASTER_KEY`
- 企业微信机器人完整 Webhook
- 外部数据 API 密钥或授权头
- 淘宝、天猫或供应商账号密码
- 可复用的登录 Cookie、Token 或浏览器会话

## 4. 主密钥轮换

轮换前准备可重新录入的企业微信 Webhook 和供应商 API 密钥。暂停自动检查，备份数据库，停止 API，替换 `SETTINGS_MASTER_KEY`，启动 API后由管理员重新保存两项秘密配置。完成单条企业微信和供应商测试后再恢复检查，并销毁旧主密钥。

直接更换主密钥而不重新保存秘密配置，会导致旧密文无法解密。

## 5. 网络与日志

对外入口必须使用 HTTPS。数据库和 Redis 只允许应用所在网络访问；生产密码不得使用 `.env.example` 中的开发默认值。

日志只记录请求 ID、错误类型、状态码、供应商错误码和脱敏对象标识。不要记录请求授权头、Webhook URL、原始 Cookie、完整供应商响应或包含个人信息的页面内容。

## 6. 数据和备份

数据库备份同样包含加密密钥材料和商业价格数据，应加密存储并限制下载权限。审计日志、价格历史和预警处理记录按公司制度保留，不允许运营自行批量删除。

发生账号泄露、异常角色提升或密钥暴露时，立即暂停自动检查，撤销相关账号和 Webhook，轮换全部密钥，保留日志并核查受影响操作。
