# 天猫比价监控运营手册

> 本手册描述完成自动采集与通知运行时后的目标态运营流程。当前公开版不会自动执行定时采集，也不会自动发送企业微信消息；在开发人员完成 Worker、调度器、合规数据源和通知客户端装配并通过端到端验收前，只能用于管理、手工导入、规则验证和演示。

## 1. 目标态系统用途

本系统只做天猫同行价格监控、企业微信提醒和处理留痕，不会自动修改商品价格。第一期仅监控“星空乐器专营店”，裸机与套装分开比价。

确定可比的同行到手价只要低于我方到手价，即使只低 `0.01 元`，也会生成预警。同价或高于我方不会预警。

真实天猫搜索必须由管理员另行选定并验收合规的 `CommerceProvider`。仓库自带的固定样例和手工 fallback 只用于开发、测试和演示，不代表可直接用于真实天猫搜索的数据服务。

## 2. 首次导入型号

1. 在“型号管理”下载运营模板。
2. 先录入 20 至 50 个重点型号，不要一次导入全店。
3. 把黄色示例行替换为真实商品链接、具体 SKU 和负责人。
4. 裸机每个型号一行；同型号的不同套装分别建立监控编号。
5. 套装必须在“套装明细”填写核心配件、型号、数量和标准价值。
6. 型号别名、旧款名称和排除词应尽量完整。
7. 上传 `.xlsx` 后逐条修改系统显示的工作表、行号和字段错误，直到导入成功。

不要在 Excel 中填写企业微信 Webhook、外部数据 API 密钥、淘宝账号或密码。

## 3. 每日工作节奏

系统默认在 `03:30、09:30、10:30、11:30、12:30、13:30、14:30、15:30、16:30、17:30、18:30、22:30` 检查，时区为 `Asia/Shanghai`。

运营上班后先看总览中的“数据正常”“今日扫描”和“采集异常”。工作时段优先处理“待处理”预警；18:30 前复查仍未处理的高价差项目。夜间预警可在次日 09:30 后统一处理。

## 4. 预警处理规则

| 处理结果 | 使用场景 | 必填内容 |
| --- | --- | --- |
| 已改价 | 已在天猫后台人工调整我方价格 | 可填写新价格或处理说明 |
| 不跟价 | 有授权价、利润、库存、赠品或渠道策略原因 | 必须选择原因，可补充说明 |
| 误报 | 型号、版本、套装配置、库存或价格口径不可比 | 必须选择原因，并说明误报点 |
| 继续观察 | 暂不处理，等待活动、库存或授权政策变化 | 建议填写复查时间或条件 |

处理前应打开同行链接，确认具体 SKU、库存、公开优惠和套装配件。搜索页区间最低价、私聊价、定金、二手、维修和缺货 SKU 不能直接作为自动跟价依据。

## 5. 裸机与套装

裸机只比较同品牌、同型号、同版本的单品具体 SKU。套装核心配件完全相同才直接比较总到手价；核心配件不同或无法确认时进入人工核对，不标记为确定低价。

赠品不默认抵扣到手价。只有已经在套装明细中登记、可量化且口径一致的配件，才用于套装参考分析。

## 6. 页面说明

| 页面 | 主要工作 |
| --- | --- |
| 总览 | 查看 12 个检查时点、今日扫描、低价事件和异常 |
| 型号管理 | 导入、启停和维护监控规则 |
| 裸机比价 | 查看可比裸机的我方价、同行最低价和库存 |
| 套装比价 | 查看同配置套装和价差 |
| 待人工分类 | 处理系统无法可靠判断的裸机、套装或排除项 |
| 预警中心 | 按裸机、套装查看并处理低价预警 |
| 历史价格 | 追溯具体 SKU 的价格和证据链接 |
| 系统设置 | 管理数据源、检查时间和加密密钥，仅管理员使用 |

## 7. 异常上报

出现“数据异常”、连续两个计划时点没有新采集记录、同一型号大面积价格缺失、企业微信没有消息或供应商字段变化时，先暂停自动检查，再按《采集故障恢复手册》处理。任何采集失败都不能当作同行低价，也不能据此人工改价。
