# 采集故障恢复手册（目标态）

> 本手册仅适用于完成生产运行时装配后的目标态系统。当前公开版尚未装配采集 Worker、`CollectionScheduler`、真实 `CommerceProvider` 和 `WecomClient`，启动 API 与管理后台不会自动采集或发送企业微信消息，因此当前公开版不执行本文的停启与恢复步骤。

## 1. 先止损

目标态生产系统出现连续两个时点无采集、价格大面积异常、供应商限流、字段契约变化或企业微信异常轰炸时，由管理员先在“系统设置”关闭自动检查。系统只暂停新任务，不删除历史数据和已有预警。

在原因确认前不要人工批量改价，也不要把价格缺失、接口错误或搜索区间最低价当作同行低价。

## 2. 快速诊断

```bash
curl -fsS http://127.0.0.1:4100/api/health
curl -fsS http://127.0.0.1:4100/api/health/collection
docker compose -f infra/docker-compose.yml ps
```

同时查看总览中的“采集异常”、最近一次采集状态和服务日志。错误信息中不得打印 Webhook、API 密钥或完整授权头。

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| database 为 down | PostgreSQL 停止、连接数耗尽或密码变化 | 恢复数据库，验证迁移版本，再重启 API |
| redis 为 down | Redis 停止、端口变化或内存不足 | 恢复 Redis，确认 AOF 可读，再重启 Worker |
| PROVIDER_RATE_LIMITED | 供应商额度或频率限制 | 保持暂停，向供应商确认配额和恢复时间，不提高抓取频率 |
| PROVIDER_CONTRACT_CHANGED | 返回字段、类型或层级变化 | 保存脱敏样例，更新映射契约测试，通过后再启用 |
| 大量价格为空 | 具体 SKU、公开优惠或库存字段缺失 | 转人工核对，不使用搜索页价格补位 |
| 企业微信发送失败 | Webhook 失效、群机器人被移除或网络故障 | 更新 Webhook，发送单条测试消息，再恢复通知 |
| 同一价格重复提醒 | 去重键或商品 SKU 标识变化 | 暂停任务，检查 `platformItemId + skuId + price`，不得直接清空预警表 |

## 3. 供应商字段契约恢复

供应商至少必须稳定提供商品 ID、商品链接、店铺、标题、具体 SKU ID 与规格、SKU 页面价、公开优惠、到手价、库存、采集时间和原始证据引用。

恢复步骤：保存一份脱敏失败响应；确认是临时错误还是正式版本变化；更新 mapper 和 fixture；运行供应商契约测试、匹配测试、价格测试和三条端到端验收；抽检不少于 20 个真实 SKU；最后再由管理员启用外部数据源。

## 4. PostgreSQL 恢复

确认备份时间和数据完整性后恢复数据库，再执行：

```bash
pnpm prisma migrate status
pnpm prisma migrate deploy
curl -fsS http://127.0.0.1:4100/api/health
```

不要在未备份时手工删除 `OfferSnapshot`、`PriceAlert`、`AlertAction` 或 `AuditLog`。这些记录用于去重、复盘和责任追踪。

## 5. Redis 恢复

Redis 恢复后先确认 `PING` 正常，再重启目标态采集 Worker。任务使用型号锁和幂等 `runId`；仍需检查是否存在长时间未结束的 RUNNING 记录。目标态实现不自动补齐停机期间全部历史时点，恢复后从下一计划时点继续。

## 6. 恢复验收

1. 数据库和 Redis 均为 `up`。
2. 用一个测试型号完成一次搜索、具体 SKU 获取、匹配和价格计算。
3. 验证同价不提醒、低 `0.01 元`提醒一次、再次降价再次提醒。
4. 验证不同配置套装只进入人工核对。
5. 验证企业微信群只收到预期的一条测试消息。
6. 观察下一个计划时点成功后，再恢复全部重点型号。

故障结束后记录开始时间、影响型号、根因、处理人、恢复时间和预防措施。
